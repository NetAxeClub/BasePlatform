# device_api 当前能力

## 1. 当前结论

截至 2026-03-17，`device_api` 已作为默认设备采集主链放行，当前放行结论为：`PASS_WITH_WAIVER`。

当前运行策略：

- 默认入口：`device_api`
- fallback 入口：`automation`
- `automation` 仅用于回退与应急，不再作为日常默认入口

当前豁免：

- 并行对比不一致集合数：目标 `<=1`，当前 `5`
- 并行对比匹配率：目标 `>=95%`，当前 `16.7%`
- strict 口径时间锚点已补齐，但计数一致性仍在收敛

正式决议见：

- [p5_acceptance_decision.json](./p5_acceptance_decision.json)
- [p5_release_notes.json](./p5_release_notes.json)
- [p5_rollout_report.json](./p5_rollout_report.json)

## 3. 协议与执行能力

当前执行面：

- Netmiko：默认主路径
- NETCONF：Huawei / H3C 主矩阵已纳入主路径
- SNMP：已补执行链和错误语义
- RESTCONF：已补执行链和错误语义
- Telemetry：仍为延期能力，默认不纳入替代范围

执行层当前具备：

- 协议级 timeout / retry 统一策略
- 单协议失败隔离
- 本地执行与南向执行统一返回合同
- `clear_history=False` 的灰度、回退和排障保留策略

## 4. 结果合同与下游联动

标准化结果当前固定保留 9 个字段：

- `hostip`
- `hostname`
- `idc_name`
- `log_time`
- `summary_plan_id`
- `plan_id`
- `collection_type`
- `collection_method`
- `execute_time`

当前合同与联动能力：

- `version` 统一归一为 `device_identity`
- 标准结果统一落到 `plan_<collection_type>`
- `collection-results/latest/` 支持按最新批次查询
- `facts` / `capabilities` / `plans-to-device` 可用于排障和能力解释
- `analysis_hooks` 保持“数据 ready 后才触发分析”的门禁
