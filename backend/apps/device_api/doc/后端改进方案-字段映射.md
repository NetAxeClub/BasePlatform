# 采集方案「数据处理」改为「字段映射」— 后端改进方案

> 状态说明（2026-03-03）：本文件保留历史参考。  
> 当前运行链路已切换为“processors + tools + metadata”，不再在入库前执行字段映射转换。

## 一、背景

前端已完成「数据处理」改为「字段映射」的改造：

- 新建/编辑/详情中，原「数据处理」步骤/Tab 已改名为「**字段映射**」，仅保留根节点选择与字段映射配置。
- 前端**不再展示**「启用函数处理」、Python 代码编辑器及任何与自定义数据处理相关的 UI。
- 新建、编辑提交时，**不再提交**有效的处理器代码与启用状态，而是固定提交：
  - `netmiko_processor_enabled: false`
  - `netconf_processor_enabled: false`
  - `netmiko_processor: ''`
  - `netconf_processor: ''`
- 字段映射相关字段（如 `netmiko_path`、`netconf_path`、`netmiko_field_mappings`、`netconf_field_mappings` 等）**仍按原逻辑提交**，与后端现有约定一致。

为保障前后端协同与数据兼容，需要后端做相应调整，本方案给出建议改动范围与验收要点。

---

## 二、涉及接口

| 接口 | 方法 | 路径（参考） | 说明 |
|------|------|--------------|------|
| 新建采集任务（子方案） | POST | `/base_platform/device_api/sub-collection-plan/` | 创建时前端会传 processor 相关为 false/空 |
| 更新采集任务（子方案） | PATCH | `/base_platform/device_api/sub-collection-plan/{id}/` | 更新时同上 |
| 子方案详情 | GET | `/base_platform/device_api/sub-collection-plan/{id}/` | 详情中不再展示处理器与代码，但字段映射字段仍需返回 |

其余接口（如采集结果列表、执行验证等）与本次改造无直接关系，可保持不变。

---

## 三、后端改进项

### 3.1 创建/更新子方案时的入参约定

**1）处理器相关字段改为可选，并支持默认值**

- `netmiko_processor_enabled`、`netconf_processor_enabled`  
  - 建议：**可选**；若未传或传 `false`，后端按「未启用」处理；若旧客户端传 `true`，可保留兼容（或统一按 false 处理，视产品是否彻底下线该功能而定）。
- `netmiko_processor`、`netconf_processor`  
  - 建议：**可选**；若未传或传空字符串，后端不执行自定义 Python 处理，仅使用字段映射做结果转换。

**2）移除或放宽「启用时代码必填」类校验**

- 若当前存在类似「当 `netmiko_processor_enabled === true` 时，`netmiko_processor` 必填」的校验，建议：
  - **方案 A（推荐）**：直接删除该校验；或  
  - **方案 B**：保留字段但仅当 `processor_enabled === true` 时才校验代码非空；前端已恒传 `false`，故不会触发该校验。

**3）字段映射相关字段**

- `netmiko_path`、`netconf_path`、`netmiko_field_mappings`、`netconf_field_mappings` 等保持现有含义与校验规则，**无需变更**，确保「仅字段映射」的配置能正常落库并参与采集结果转换。

### 3.2 子方案详情返回

- 详情接口返回中，可继续包含 `netmiko_processor_enabled`、`netconf_processor_enabled`、`netmiko_processor`、`netconf_processor` 等字段（便于旧客户端或未来扩展）；若后端希望精简响应，也可不再返回处理器相关字段。
- **必须保留**字段映射相关字段的返回（如 `netmiko_path`、`netconf_path`、`netmiko_field_mappings`、`netconf_field_mappings`），供前端「字段映射」Tab 只读展示。

### 3.3 采集执行与结果处理逻辑

- 若当前执行采集（如 NETMIKO/NETCONF 执行）会根据 `netmiko_processor_enabled`/`netconf_processor_enabled` 决定是否调用自定义 Python 代码：
  - 当这两个字段为 `false` 或未传时，**应跳过**自定义代码执行，仅使用字段映射（如 `netmiko_field_mappings`/`netconf_field_mappings`）对原始结果做结构化转换。
- 确保「仅配置字段映射、不配置处理器」的任务能正常执行并产出预期结果，不因缺少 processor 代码而报错或中断。

### 3.4 数据迁移与兼容（可选）

- **历史数据**：已有任务中可能存在 `netmiko_processor_enabled: true` 或带代码的 `netmiko_processor`。建议：
  - 若产品上已彻底下线「自定义数据处理」：可在后台将历史任务统一置为 `netmiko_processor_enabled=false`、`netconf_processor_enabled=false`，并将 processor 代码清空或归档，避免执行时仍走旧逻辑。
  - 若仅前端隐藏、后端暂保留能力：可不做数据迁移，仅保证在 `processor_enabled=false` 或代码为空时不执行处理器即可。

---

## 四、验收要点

| 项 | 说明 |
|----|------|
| 新建任务 | 前端仅提交字段映射 + processor 为 false/空；后端能成功创建，且不报「处理器代码必填」等错误。 |
| 编辑任务 | 同上，更新时 processor 为 false/空，字段映射可正常更新并保存。 |
| 详情接口 | 返回中包含字段映射相关字段，前端「字段映射」Tab 能正确展示根节点与映射关系。 |
| 执行验证 | 仅配置字段映射、未配置处理器的任务，执行采集/验证接口能正常完成，结果依赖字段映射正确转换。 |
| 历史数据 | 已有带 processor 配置的任务，在未做数据迁移的前提下仍可正常查看与执行（或按产品决策做一次性迁移）。 |

---

## 五、小结

- **必做**：创建/更新接口将处理器相关字段视为可选并支持默认（false/空）；移除或放宽「启用时代码必填」校验；执行逻辑在 processor 未启用或代码为空时仅使用字段映射。
- **必做**：详情接口继续返回字段映射相关字段，供前端「字段映射」Tab 展示。
- **可选**：详情是否仍返回 processor 字段、是否对历史数据做一次性迁移，由产品与后端约定即可。

按上述调整后，前端「仅字段映射」的改造可与后端无缝配合，无需前端再传处理器代码或启用状态。
