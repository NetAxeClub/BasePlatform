# device_api 前端 PRD

## 1. 文档目的

本文档用于定义 `device_api` 前端页面的产品范围和页面目标，供产品、UI、前端统一理解。

本期只做两类输出：

- 前端 PRD
- 原型设计文档

除这两份文档外，不再保留其它前端过程文档作为设计依据。

## 2. 产品背景

`device_api` 当前对外可产品化的核心能力仍然是设备数据采集。

前端页面必须围绕网络运维的实际工作流设计：

1. 采集前：确认设备条件、画像和绑定是否合理
2. 采集中：查看批次状态、问题设备、问题子方案
3. 采集后：根据建议决定去改绑定、查执行、还是查方案

因此，一级菜单统一归属为：`数据采集`

二级菜单固定为：

1. `设备画像`
2. `采集方案`
3. `执行总览`

## 3. 目标用户

### 主要用户

- 网络运维工程师
- 平台运维 / 自动化管理员

### 用户最关心的问题

- 这台设备现在为什么这样采
- 问题到底在设备、账号、协议，还是方案本身
- 哪个批次、哪台设备、哪个子方案最需要先处理
- 下一步应该去哪个页面操作

## 4. 本期目标

- 让运维在 3 个主页面内完成“找设备、看方案、看执行”的主流程
- 让页面之间跳转清楚，不需要靠用户自己拼上下文
- 让 UI 出图时就能明确默认态、空态、错误态和点击行为

## 5. 本期范围

### 主页面

- `设备画像`
- `采集方案`
- `执行总览`

### 关联页面

- `画像详情`
- `绑定调整`
- `方案验证`
- `子项测试`
- `执行追踪`
- `问题处置`

总计：`9` 张页面

## 6. 非范围

本期不做：

- 全局导航和应用壳子
- 全量资产设备选择中心
- 方案发布 / 回滚 / 版本管理
- 批量重试 / 统一重跑
- 处置结果提交 / 关闭问题
- 绑定变更预览
- 样例持久化
- 实时 worker / 队列运行看板

## 7. 后端能力边界

原型和页面只允许建立在当前已经存在的后端能力上。

### 已有能力

- 设备事实、能力、绑定、追踪、分析建议
- 父方案 CRUD
- 子方案 CRUD
- 父方案验证
- 父方案整套测试
- 子方案单项测试
- 批次结果、设备结果、子方案结果、深度结果查询
- 手动刷新分析建议

### 禁止假设的能力

- 全量设备选择接口
- 绑定预览接口
- 问题处置提交接口
- 统一重试接口
- 批量重试接口
- 方案发布接口

## 8. 页面定位

| 页面 | 页面定位 | 页面只回答的问题 |
|---|---|---|
| 设备画像 | 设备入口判断页 | 这台设备是谁、按什么采、值不值得继续深挖 |
| 画像详情 | 单设备证据页 | 这台设备最近执行事实和建议依据是什么 |
| 绑定调整 | 绑定编辑页 | 当前 binding 怎么改 |
| 采集方案 | 方案治理页 | 系统里有哪些父方案和子方案，方案本身是否稳定 |
| 方案验证 | 父方案验证页 | 一整套父方案在某台设备上验证结果如何 |
| 子项测试 | 单项测试页 | 某个子方案能不能单独跑通 |
| 执行总览 | 值班主页面 | 最近批次哪里有问题 |
| 执行追踪 | 执行细节页 | 某台设备某次执行到底哪一步出错 |
| 问题处置 | 处置引导页 | 当前问题应该去哪个已有页面处理 |

## 9. 核心流程

### 流程 1：值班排障

1. 进入 `执行总览`
2. 找到失败设备
3. 点状态或错误进入 `执行追踪`
4. 判断是设备问题还是方案问题
5. 去 `设备画像` 或 `采集方案`

### 流程 2：设备纳入前检查

1. 进入 `设备画像`
2. 找到目标设备
3. 查看绑定、协议和账号条件
4. 如有问题，进入 `绑定调整`
5. 如需验证方案，进入 `方案验证`

### 流程 3：方案治理

1. 进入 `采集方案`
2. 查看父方案和子方案
3. 做父方案验证或子项测试
4. 从失败样本跳 `执行追踪`

## 10. 页面级需求

## 10.1 设备画像

### 页面目标

- 先找设备
- 再看绑定和能力
- 再决定去执行追踪还是绑定调整

### 页面必须包含

- 左侧设备列表
- 右侧设备摘要
- 当前绑定卡
- 协议与账号条件卡
- 最近执行摘要
- 最近建议

### 页面边界

- 当前页面只覆盖“已纳入采集治理设备”
- 不能表达为全量资产设备页

### 主动作

- `查看画像详情`
- `调整绑定`
- `自动重绑`

## 10.2 采集方案

### 页面目标

- 查看父方案
- 查看子方案
- 管理方案
- 发起验证和测试

### 页面必须包含

- 父方案主表
- 子方案编排区
- 字段映射入口
- 同步子方案入口
- 方案验证入口
- 整套测试入口

### 主动作

- `新增父方案`
- `查看字段映射`
- `同步默认子方案`

## 10.3 执行总览

### 页面目标

- 第一屏看出最近批次哪里有问题
- 第一屏就能定位问题设备
- 第一屏就能区分设备问题、方案问题、建议问题

### 页面必须包含

- 批次筛选区
- 批次总览卡
- 设备执行表
- 分析建议区

### 主动作

- `重置筛选`
- `刷新分析结果`

## 11. 默认态、空态、错误态要求

### 默认态

- `设备画像`：左侧显示设备列表，右侧显示“请选择设备”
- `采集方案`：显示父方案主表和当前父方案子方案区
- `执行总览`：默认展示最近批次

### 空态

空态必须同时包含：

- 当前为什么没数据
- 可能原因
- 下一步动作

### 错误态

- 错误态不能清空整页结构
- 标题、筛选区、已选中对象必须保留

## 12. 页面跳转规则

- `执行总览` 点设备名称/IP -> `设备画像`
- `执行总览` 点状态/失败子方案数/主要错误 -> `执行追踪`
- `执行总览` 点当前方案 -> `采集方案`
- `执行总览` 点推荐动作 -> `问题处置`
- `设备画像` 点查看详情 -> `画像详情`
- `设备画像` 点调整绑定 -> `绑定调整`
- `设备画像` 点当前方案 -> `采集方案`
- `采集方案` 点方案验证 -> `方案验证`
- `采集方案` 点单项测试 -> `子项测试`
- `采集方案` 点失败样本 -> `执行追踪`

## 13. 产品验收标准

- UI 只根据本 PRD 和原型设计文档即可出图
- 任一页面都没有依赖后端不存在能力的伪按钮
- 页面默认态、空态、错误态清楚
- 点击入口语义清楚，不混乱
- 设备、方案、执行三条主线能形成闭环跳转

UI 交付原型时，必须覆盖：

- 核心操作态
