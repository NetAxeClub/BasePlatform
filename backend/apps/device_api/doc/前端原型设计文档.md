# device_api 前端原型设计文档

## 1. 文档目的

本文档用于指导 UI 直接产出 `device_api` 前端原型图。

要求：

- 不空谈
- 不泛指
- 不写将来能力
- 每一页明确到展示形态、点击行为、默认态、空态、错误态

本文件只服务原型出图，不讨论前端开发拆分。

## 2. 原型总规则

## 2.1 页面数量

本期必须画出 9 张页面：

1. `设备画像`
2. `画像详情`
3. `绑定调整`
4. `采集方案`
5. `方案验证`
6. `子项测试`
7. `执行总览`
8. `执行追踪`
9. `问题处置`

## 2.2 统一布局规则

每个页面都按以下顺序摆放：

1. 页面标题
2. 页面说明
3. 顶部筛选或参数区
4. 主内容区
5. 主动作区

## 2.3 统一状态规则

每页都必须画：

- 默认态
- 空态
- 核心操作态

以下页面额外画错误态：

- `设备画像`
- `方案验证`
- `子项测试`
- `执行总览`
- `执行追踪`

## 2.4 统一按钮规则

每页主按钮最多 3 个。

按钮只允许是真实能力：

- 已有查询
- 已有编辑
- 已有验证
- 已有测试
- 已有跳转

不得画出：

- 标记已处理
- 关闭问题
- 批量重跑
- 发布方案
- 版本对比

## 3. 页面原型说明

## 3.1 设备画像

### 页面用途

查看单设备当前绑定、采集条件和最近执行情况。

### 页面布局

桌面端为左右结构：

- 左侧固定设备列表区，宽度 `360px` 到 `420px`
- 右侧为当前设备内容区

### 左侧区域内容

从上到下固定为：

1. 页面标题：`设备画像`
2. 范围说明：`当前页面展示已纳入采集治理的设备`
3. 搜索框
4. 快捷筛选标签
5. 设备列表
6. 分页

### 左侧设备列表

顶部固定 3 个快捷筛选：

- `全部治理设备`
- `有问题设备`
- `已绑定设备`

每行两层展示：

第一层：

- 设备名称
- 管理 IP
- 当前状态标签

第二层：

- 厂商 / 型号
- 资产类型
- 当前激活方案
- 建议数或风险标签

点击整行：

- 右侧切换到当前设备

### 右侧区域内容

从上到下固定为：

1. 设备身份卡
2. 当前绑定卡
3. 协议与账号条件卡
4. 最近执行摘要卡
5. 最近建议卡
6. 主动作区

### 设备身份卡

展示：

- 设备名称
- 管理 IP
- 序列号
- 厂商
- 型号
- 软件版本
- 补丁版本
- 资产类型
- 当前画像
- 最近识别状态

### 当前绑定卡

展示：

- 当前 active binding
- 父方案名称
- binding_source
- use_local
- execute_node
- 同设备其他 binding 列表

若有风险，顶部显示标签：

- `未绑定`
- `绑定冲突`
- `方案不匹配`

### 协议与账号条件卡

只画判断结果，不画原始字段：

- CLI：满足 / 不满足 / 未知
- NETCONF：满足 / 不满足 / 未知
- SNMP：满足 / 不满足 / 未知
- 当前方案协议条件：满足 / 不满足
- 账号条件：完整 / 缺失 / 未知

卡片底部增加“推荐候选 binding”列表。

### 最近执行摘要卡

展示：

- 最近执行时间
- 总体状态
- 成功子方案数
- 失败子方案数
- 覆盖缺口子方案数
- 主要错误摘要

点击规则：

- 点失败子方案数 -> `执行追踪`
- 点主要错误摘要 -> `执行追踪`

### 最近建议卡

只展示前 3 条建议。

每条结构固定：

- 建议类型
- 建议说明
- 推荐动作按钮

按钮只允许：

- `去看执行`
- `去调整绑定`
- `去看方案`

### 主动作区

固定 3 个按钮：

- `查看画像详情`
- `调整绑定`
- `自动重绑`

### 默认态

- 左侧显示设备列表第一页
- 右侧显示“请选择设备”

### 空态

#### 左侧无设备

- 文案：`当前筛选条件下没有设备`
- 按钮：`重置筛选`

#### 设备无执行结果

- 文案：`暂无最近采集结果`
- 按钮：
  - `去采集方案`
  - `查看绑定调整`

### 错误态

#### 左侧列表加载失败

- 保留右侧区域
- 左侧显示：
  - `设备列表加载失败`
  - `重新加载`

#### 右侧设备加载失败

- 保留左侧选中态
- 右侧显示：
  - `当前设备信息加载失败`
  - `重新加载`

## 3.2 画像详情

### 页面用途

展开单设备完整证据链。

### 页面布局

从上到下固定：

1. 设备摘要头
2. 绑定与建议摘要
3. 最近执行时间线
4. 子方案状态表
5. 原始结果 / 处理结果区
6. 主动作区

### 子方案状态表

列固定为：

- 子方案名称
- collection_type
- 启用协议
- 最近状态
- 最近运行时间
- 错误摘要
- 操作

操作只允许：

- `查看执行追踪`
- `查看方案验证`

### 主动作区

按钮固定：

- `调整绑定`
- `查看执行追踪`
- `查看方案验证`

## 3.3 绑定调整

### 页面用途

编辑 `PlansToDevice`。

### 页面布局

从上到下固定：

1. 当前 active binding 摘要
2. 其他 binding 列表
3. 推荐候选 binding 区
4. 编辑表单
5. 自动重绑区
6. 提交反馈区

### 编辑表单字段

只允许：

- plan
- profile_code
- is_active
- use_local
- execute_node

### 主按钮

- `保存绑定`
- `执行自动重绑`
- `返回设备画像`

### 提交后反馈

成功后固定提示：

- `返回设备画像`
- `去方案验证`
- `去子项测试`

## 3.4 采集方案

### 页面用途

父方案和子方案治理主页面。

### 页面布局

从上到下固定：

1. 页面标题与说明
2. 统计卡区
3. 父方案主表
4. 当前选中父方案的子方案编排区

### 顶部主按钮

固定：

- `新增父方案`
- `查看字段映射`
- `同步默认子方案`

### 统计卡

固定 5 张：

- 父方案总数
- 启用方案数
- 异常方案数
- 最近验证失败方案数
- 最近失败设备数

### 父方案主表

列固定：

- 父方案名称
- 适用厂商 / 资产类型
- profile_code
- 子方案数量
- 启用状态
- 最近验证状态
- 最近失败设备数
- 操作

操作列固定：

- `编辑`
- `删除`
- `方案验证`
- `整套测试`

点击父方案名称或整行：

- 切换下方子方案区

### 子方案编排区

列固定：

- 子方案名称
- collection_type
- 协议
- 命令 / XML 模板摘要
- 解析方式
- 处理器
- 是否启用
- 最近失败数
- 最近样例结果
- 操作

操作列固定：

- `编辑`
- `删除`
- `单项测试`
- `查看失败样本`

### 空态

#### 没有父方案

- 文案：`当前暂无采集方案`
- 按钮：`新增父方案`

#### 有父方案但无子方案

- 文案：`当前父方案下暂无子方案`
- 按钮：
  - `新增子方案`
  - `同步默认子方案`

## 3.5 方案验证

### 页面用途

结构化展示父方案验证结果。

### 页面布局

从上到下固定：

1. 父方案摘要
2. 验证参数区
3. 验证汇总卡
4. 按 collection_type 分组结果区
5. 失败项动作区

### 验证参数区

字段：

- device_ip
- serial_num
- use_local
- south_driver

按钮：

- `执行验证`

### 验证汇总卡

固定展示：

- success_count
- failed_count
- skipped_count
- total_plans

### 分组结果区

每条结果展示：

- 子方案名称
- 状态
- message
- 各协议结果摘要

### 失败项动作区

只允许按钮：

- `查看子方案定义`
- `进入单项测试`

### 错误态

- 验证失败时保留参数区
- 结果区显示后端返回的 message

## 3.6 子项测试

### 页面用途

独立测试某个子方案。

### 页面布局

从上到下固定：

1. 子方案摘要
2. 测试参数区
3. 执行结果摘要区
4. 协议结果区
5. 错误摘要区
6. 下一步动作区

### 测试参数区

字段：

- device_ip
- serial_num
- use_local
- south_driver

按钮：

- `执行单项测试`

### 协议结果区

分 5 块：

- NETMIKO
- NETCONF
- SNMP
- RESTCONF
- TELEMETRY

每块固定三层：

- 协议标题
- 协议状态
- 结果摘要 / 错误摘要

### 下一步动作区

固定按钮：

- `去设备画像`
- `去执行追踪`
- `返回方案验证`

### 错误态

- 保留测试参数
- 保留已选子方案摘要
- 错误摘要区显示后端 message

## 3.7 执行总览

### 页面用途

值班主页面。

### 页面布局

从上到下固定：

1. 页面标题与说明
2. 批次筛选区
3. 批次总览卡
4. 设备执行表
5. 分析建议区

### 批次筛选区

字段固定：

- execute_time
- manage_ip
- summary_plan_id
- task_status
- recommendation_code

按钮固定：

- `重置筛选`
- `刷新分析结果`

### 批次总览卡

固定 6 张：

- 设备总数
- 成功数
- 部分成功数
- 失败数
- 子方案失败数
- 覆盖缺口数

下方必须额外展示：

- 协议失败聚合
- 跳过原因聚合

### 设备执行表

列固定：

- 设备名称
- 设备 IP
- 当前方案
- 当前状态
- 失败子方案数
- 跳过子方案数
- 覆盖缺口数
- 主要错误
- 建议类型
- 推荐动作
- 操作

### 设备执行表点击规则

- 点设备名称 -> `设备画像`
- 点设备 IP -> `设备画像`
- 点当前方案 -> `采集方案`
- 点当前状态 -> `执行追踪`
- 点失败子方案数 -> `执行追踪`
- 点主要错误 -> `执行追踪`
- 点推荐动作 -> `问题处置`
- 点操作列按钮 -> `执行追踪`

### 分析建议区

每条建议固定展示：

- 建议类型
- 影响设备数
- 建议说明
- 推荐动作按钮

按钮只允许：

- `去看设备`
- `去看方案`
- `去看追踪`
- `去做处置`

### 默认态

- 若存在批次，默认显示最近批次
- 若不存在批次，显示空态卡

### 空态

文案固定：

- `当前暂无采集执行记录`
- 可能原因
- 下一步按钮：
  - `去设备画像`
  - `去采集方案`

### 错误态

- 标题和筛选区保留
- 主内容区显示：
  - `执行数据加载失败`
  - `重新加载`

## 3.8 执行追踪

### 页面用途

查看某台设备某次执行的详细过程。

### 页面布局

从上到下固定：

1. 顶部执行摘要
2. 子方案列表
3. 当前子方案明细区
4. 深度结果详情区
5. 跳转区

### 顶部执行摘要

固定字段：

- 设备名称
- 设备 IP
- execute_time
- 父方案名称
- 总体状态

### 子方案列表

列固定：

- 子方案名称
- collection_type
- 状态
- 错误摘要
- 操作

操作只允许：

- `查看明细`

### 深度结果详情区

原型必须体现两种情况：

1. 有 `result_detail`
2. 无 `result_detail`，退化为 `sub_collection_detail`

### 跳转区

固定按钮：

- `去设备画像`
- `去方案验证`

### 错误态

- 保留顶部执行摘要
- 明细区显示：
  - `结果详情加载失败`
  - `重新加载`

## 3.9 问题处置

### 页面用途

只读处置引导页。

### 页面布局

从上到下固定：

1. 当前问题摘要
2. 建议类型与说明
3. 证据摘要
4. 子方案证据摘要
5. 推荐动作区

### 顶部说明文案

必须固定出现：

`当前页面只用于帮助判断处理方向，不支持直接提交处置结果。`

### 推荐动作区

固定按钮：

- `去设备画像`
- `去绑定调整`
- `去方案验证`
- `去子项测试`
- `去执行追踪`

### 禁止项

不得出现：

- `标记已处理`
- `关闭问题`
- `提交处置结果`

## 4. 原型出图要求

UI 最终交付原型时，每页至少要能看出：

- 页面默认进来时长什么样
- 页面没有数据时长什么样
- 用户点击哪个区域会跳哪里
- 哪些按钮是真实动作
- 哪些页面只是引导，不是提交页

## 5. 原型评审标准

原型只有同时满足以下条件才算合格：

- 9 张页面都已出图
- 每页默认态清楚
- 每页空态清楚
- 核心点击规则清楚
- 页面没有后端不存在的能力
- UI 和产品只看这份文档就能达成一致，不再需要额外猜测页面逻辑
