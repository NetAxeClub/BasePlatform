# device_api 采集主链替代实施与验收清单

## 1. 目标

本清单用于细化 `T-20260316-01`，目标是把 `device_api` 补齐为默认设备数据采集主链，功能上可替代当前 `automation` 的设备采集能力。

本次替代的边界必须固定为：

- 默认采集入口切到 `device_api`
- `automation` 代码逻辑不改，继续保留为历史兼容和生产兜底
- 新增采集能力、模板、处理器、测试与文档只进入 `device_api`
- 下游消费继续以 `device_api` 标准化结果合同为准，不回退到 legacy 结果表语义

## 2. 范围与非目标

### 2.1 范围内

- `backend/apps/device_api/tasks.py`
  - 主调度 `plan_collect_device_main`
  - 单设备任务 `plan_collect_device`
- `backend/apps/device_api/services_new.py`
  - 本地执行与南向驱动兼容执行
- `backend/apps/device_api/connection_manager.py`
  - Netmiko / NETCONF / SNMP / RESTCONF / Telemetry 执行层
- `backend/apps/device_api/platform_profiles.py`
  - 平台画像、默认方案、自动绑定
- `backend/apps/device_api/tools/collect_device.py`
  - 设备筛选、账号装配、`PlansToDevice` 绑定读取
- `backend/apps/device_api/processors/`、`backend/apps/device_api/tools/`
  - 厂商解析、标准化和兜底规范化
- `backend/apps/device_api/models_api.py`、`backend/apps/device_api/contract.py`
  - 标准结果合同、入库与上下文字段
- `backend/apps/device_api/views.py`
  - 验证、执行、查询、绑定、事实和能力接口
- `backend/apps/device_api/tests.py`、`backend/apps/device_api/test_collection_contract.py`、`backend/apps/device_api/test_interface_analysis_hooks.py`
  - 单测、合同测试、联动测试
- `backend/apps/device_api/management/commands/`
  - legacy 绑定桥接、规则导入、索引维护

### 2.2 非目标

- 不改 `apps.automation` 采集实现逻辑
- 不删除 `automation` 的采集入口、模型或历史数据表
- 不直接改造 `asset.NetworkDevice` 结构
- 不把 Telemetry 占位能力当作已完成能力发布
- 不要求一步到位删除所有 legacy 入口，只要求 `device_api` 成为默认主入口

## 3. 当前实现现状与主要缺口

基于 2026-03-16 当前代码现状，已经具备以下基础：

- `device_api` 已有独立主调度、单设备采集、连接复用和标准化入库链路
- `PlansToDevice` 已经成为设备与采集方案的绑定关系源，`get_auto_device()` 已从该表取数
- `PlatformProfileService` 已提供 Huawei / H3C / Ruijie / Hillstone / Cisco / ZTE / Maipu / Mellanox / Centec 的内置画像、默认方案和自动绑定能力
- `contract.py` 已冻结标准结果上下文字段，`analysis_hooks.py` 已接上批次分析触发
- 已有 `sync_legacy_plan_bindings`、`import_legacy_collection_rules` 作为并行桥接工具

当前仍存在的主要缺口：

- 厂商处理器覆盖不均衡
  - Huawei / H3C 处理器最完整
  - Cisco / Ruijie / Hillstone 仅覆盖部分采集类型
  - ZTE / Maipu / Mellanox / Centec 仍以 `tools/` 兜底为主，专属 `processors/` 不完整
- 协议能力覆盖不均衡
  - Netmiko 是当前主路径
  - NETCONF 主要集中在 Huawei / H3C / Cisco
  - SNMP / RESTCONF / Telemetry 还缺真实生产级覆盖
- `connection_manager.py` 中 `execute_telemetry_subscribe()` 仍是 TODO，占位能力不能进入替代验收
- 当前主调度会在每批任务前清空 `plan_*` 与子任务结果，需要先明确该清理策略是否符合切主链后的运行要求
- 现有测试已覆盖合同、部分调度和分析触发，但还缺“对齐 automation 输出”的样本回归与厂商矩阵验收
- “何时走 device_api，何时回退 automation”的运行门禁和发布回退手册还没有形成统一文档
