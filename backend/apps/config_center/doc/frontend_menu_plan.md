# config_center 前端菜单与页面规划

## 1. 文档目的

本文档基于 [README.md](./README.md) 中对 `apps.config_center` 的产品定位与边界定义，给出前端信息架构、菜单规划、页面功能定位和基础交互逻辑建议，用于：

- 指导后续前端页面设计与路由规划
- 统一产品、后端、前端对 `config_center` 的界面认知
- 避免页面设计再次回到“设备连接 / 设备采集 / 配置下发执行”视角

本文档默认前提：

- `config_center` 面向“配置对象管理与治理”
- `device_api` 面向“设备连接、采集执行、配置下发抽象”
- 前端主流程必须围绕“配置快照”展开，而不是围绕“南向执行”展开

## 2. 设计原则

### 2.1 页面主轴

前端产品主轴建议统一为：

`配置快照 -> 版本追溯 -> 合规检查 -> 结构化视图 -> 漂移治理 -> 策略审计`

其中，“配置快照”是全产品的核心对象，其他页面都应能回溯到具体快照或具体快照对。

### 2.2 菜单设计原则

- 一级菜单只保留产品能力，不暴露研发调试语义
- 调试工具、模板调试、Git 原始浏览等能力不进入主产品导航
- 页面之间尽量采用“列表 -> 详情 -> 下钻分析”的统一体验
- 关键分析页都要支持从“某次快照”直接带参进入
- 所有治理动作都需要保留审计记录

### 2.3 角色原则

建议前端至少区分以下角色：

- 只读角色：可看快照、版本、合规、结构化、漂移、审计
- 治理角色：可处理漂移、维护豁免和白名单
- 策略管理员：可管理规则、基线、策略版本、激活与回滚
- 系统管理员：可访问内部工具域和管理级调试能力

## 3. 一级菜单总览

建议主产品使用 7 个一级菜单，另加 1 个管理员工具域。

| 一级菜单 | 建议子页面 | 页面数量 | 主要角色 |
|---|---|---:|---|
| 总览 | 配置治理首页 | 1 | 全角色 |
| 配置快照 | 快照列表、快照详情、快照时间线 | 3 | 全角色 |
| 版本对比 | 版本对比工作台 | 1 | 全角色 |
| 合规与基线 | 合规结果、规则与基线管理 | 2 | 只读 / 策略管理员 |
| 结构化配置 | 结构化快照、对象级对比 | 2 | 全角色 |
| 漂移治理 | 漂移列表、白名单与豁免管理 | 2 | 只读 / 治理角色 |
| 策略与审计 | 策略管理、审计记录 | 2 | 治理角色 / 策略管理员 |
| 管理工具 | 模板调试、Git 浏览、文件树、规则调试工具 | 1 个工具域 | 系统管理员 |

合计建议页面数：

- 主产品页面 13 个
- 内部工具域 1 组

## 5. 页面规划明细

### 5.1 总览

#### 页面：配置治理首页

功能定位：

- 作为 `config_center` 首页，展示配置治理当前状态
- 给运维、治理、审计角色提供统一入口
- 帮助用户快速发现高风险设备、异常漂移和合规风险

核心内容：

- 快照总量、昨日新增、采集覆盖率
- 合规通过率、失败规则数、高风险命中数
- 最近 24 小时漂移趋势
- 高风险设备 Top N
- 待处理豁免 / 即将到期豁免
- 最近治理动作与审计摘要

基本交互逻辑：

- 顶部提供时间范围、设备范围、厂商范围筛选
- 指标卡片点击后跳到对应列表页并自动带筛选参数
- 风险图表点击后跳转漂移列表或合规结果页
- 首页不提供设备连接、采集执行和配置下发动作

### 5.2 配置快照

#### 页面：快照列表

功能定位：

- 作为主入口展示配置快照历史
- 支持按设备、配置类型和时间筛选快照
- 提供“最新视图”和“历史视图”两种浏览模式

建议字段：

- 设备名称 / IP / 厂商 / 平台
- 快照类型，建议区分运行配置、启动配置等
- 采集时间
- 内容摘要 / 哈希
- 快照状态
- 合规状态摘要
- 漂移状态摘要
- 来源，建议区分来自 `device_api` 还是兼容链路

基本交互逻辑：

- 顶部筛选区支持设备、厂商、配置类型、时间区间、状态过滤
- 列表支持切换“按设备最新快照”和“全部历史快照”
- 点击某条记录进入快照详情
- 支持从列表直接发起“与上一版本对比”“查看合规”“查看漂移”

#### 页面：快照详情

功能定位：

- 作为快照对象的枢纽页
- 聚合展示某次快照的原文、元数据、合规、结构化和漂移结果

建议页面结构：

- 顶部：设备信息、采集时间、配置类型、快照 ID、来源、状态
- Tab：原文、元数据、版本关系、合规结果、结构化结果、漂移结果、审计记录

基本交互逻辑：

- 默认进入“原文”Tab，支持代码高亮、全文检索、行号定位
- “版本关系”Tab 支持跳到上一版、下一版或时间线视图
- “合规结果”Tab 展示规则命中摘要并支持下钻
- “结构化结果”Tab 展示对象树入口
- “漂移结果”Tab 展示与上一有效快照的差异摘要
- 所有下钻页都应保持“返回当前快照”能力

#### 页面：快照时间线

功能定位：

- 以设备维度查看配置演化过程
- 帮助用户理解配置变化节奏和关键变更点

核心内容：

- 时间轴上的快照点
- 每次快照的简要变化摘要
- 关键事件标记，如首次违规、首次高风险漂移、策略命中

基本交互逻辑：

- 先选择设备，再展示该设备时间线
- 点击时间节点进入对应快照详情
- 支持相邻版本快速对比
- 支持仅显示有变更的节点或仅显示异常节点

### 5.3 版本对比

#### 页面：版本对比工作台

功能定位：

- 提供文本层版本比较能力
- 面向运维和审计用户查看任意两次快照间差异

核心内容：

- 左右版本选择器
- 文本 diff 视图
- 关键变化摘要
- 版本元数据对照

基本交互逻辑：

- 支持三种进入方式：从快照详情进入、从时间线进入、独立选择两个快照
- 默认推荐“当前快照 vs 上一有效快照”
- 支持切换并排视图和统一 diff 视图
- 支持按关键字过滤 diff
- 可一键跳到结构化对象级对比

### 5.4 合规与基线

#### 页面：合规结果

功能定位：

- 查看某次快照或某批快照的合规检查结果
- 体现“合规结果强绑定快照”的产品语义

核心内容：

- 合规总体评分或通过率
- 命中规则数量和风险等级分布
- 规则维度明细
- 快照维度历史变化

基本交互逻辑：

- 默认支持两种视角切换：按快照看、按规则看
- 从快照详情进入时，自动定位到当前快照结果
- 点击某条规则可查看规则解释、命中证据和整改建议
- 支持对比两个快照的合规变化

#### 页面：规则与基线管理

功能定位：

- 管理合规规则树、厂商规则和安全基线
- 面向策略管理员维护规则生命周期

核心内容：

- 规则树
- 规则详情
- 规则版本历史
- 适用厂商 / 平台范围
- 启停状态和发布状态

基本交互逻辑：

- 左侧规则树，右侧规则详情
- 支持预览、校验、发布、停用、回滚
- 发布前必须展示影响范围与校验结果
- 所有变更动作要求填写变更说明，并写入审计记录

### 5.5 结构化配置

#### 页面：结构化快照

功能定位：

- 将配置文本转化为统一结构化对象进行浏览
- 给治理和分析用户提供跨厂商一致的查看方式

核心内容：

- 对象树
- 对象详情面板
- schema 标准字段展示
- 解析状态与解析异常提示

基本交互逻辑：

- 从快照详情进入时直接加载该快照的结构化结果
- 左侧对象树按对象类型分组，如接口、VLAN、ACL、路由、NAT 等
- 点击对象后右侧展示标准字段和值
- 若解析失败，页面提示失败范围和原因，不暴露底层调试细节给普通角色

#### 页面：对象级对比

功能定位：

- 基于结构化结果做对象级 diff
- 帮助用户理解“究竟哪类对象发生了什么变化”

核心内容：

- 对比快照选择器
- 对象类型过滤器
- 新增 / 删除 / 变更对象列表
- 对象字段级差异视图

基本交互逻辑：

- 默认比较当前快照与上一有效快照
- 支持按对象类型过滤，只看 ACL、接口、路由等
- 点击对象进入字段级变更详情
- 可标记某类差异为白名单候选或豁免候选

### 5.6 漂移治理

#### 页面：漂移列表

功能定位：

- 展示基于结构化快照生成的漂移结果
- 帮助治理角色快速识别真正需要处理的风险

核心内容：

- 漂移对象列表
- 风险等级
- 漂移类型
- 关联快照对
- 命中策略
- 当前处理状态

基本交互逻辑：

- 支持按风险等级、设备、对象类型、状态、是否豁免筛选
- 列表支持切换“全部漂移”和“仅异常漂移”
- 点击进入漂移详情，查看变化说明、风险理由和关联策略
- 支持治理角色直接发起“加入白名单”“申请豁免”“填写风险说明”

#### 页面：白名单与豁免管理

功能定位：

- 管理长期允许变更和临时例外
- 避免正常业务变更被持续误报

核心内容：

- 白名单规则列表
- 豁免记录列表
- 生效范围
- 生效期限
- 创建人和审批信息

基本交互逻辑：

- 支持区分长期白名单和临时豁免
- 新增豁免时必须填写对象范围、原因、到期时间
- 到期前在首页和列表中给予提醒
- 豁免失效后自动恢复进入漂移待处理视图

### 5.7 策略与审计

#### 页面：策略管理

功能定位：

- 管理漂移策略、治理策略及其版本
- 面向治理与策略管理员做策略生命周期控制

核心内容：

- 策略列表
- 策略详情
- 版本记录
- 预览 / 校验结果
- 激活状态

基本交互逻辑：

- 支持草稿、已发布、已停用等状态流转
- 激活前必须做预览和校验
- 支持策略回滚到历史版本
- 所有激活和回滚动作都要记录操作人、时间和说明

#### 页面：审计记录

功能定位：

- 统一查看配置治理过程中的关键动作
- 满足追责、回放和合规检查需求

核心内容：

- 操作时间
- 操作人
- 动作类型
- 关联对象，快照、策略、规则、豁免等
- 变更摘要
- 审计详情

基本交互逻辑：

- 支持按人、时间、设备、动作类型和对象类型筛选
- 点击记录可查看上下文详情
- 支持从快照详情、策略详情、规则详情反查审计记录

### 5.8 管理工具

#### 页面组：内部调试与模板工具

功能定位：

- 承接当前存量的 regex、TTP、TextFSM、Jinja2、Git 原始浏览、文件树等研发调试能力
- 明确与主产品域隔离

使用原则：

- 默认不出现在普通用户导航中
- 仅管理员可见
- 路由和视觉上应与主产品做明显分层
- 文案上标注“内部工具”或“管理员工具”

## 6. 核心页面流转关系

建议采用以下主链路：

1. 用户从“配置治理首页”发现异常设备或风险
2. 点击进入“快照列表”并定位到相关设备快照
3. 进入“快照详情”查看原文、合规、结构化和漂移摘要
4. 需要文本层追溯时进入“版本对比工作台”
5. 需要对象层分析时进入“对象级对比”
6. 需要治理处理时进入“漂移列表”或“白名单与豁免管理”
7. 需要规则或策略调整时进入“规则与基线管理”或“策略管理”
8. 最终通过“审计记录”回看治理动作闭环

## 8. 页面级统一交互规范

建议所有产品页遵循统一交互模式：

### 8.1 顶部筛选区

- 时间范围
- 设备范围
- 厂商 / 平台
- 状态
- 风险等级

### 8.2 主内容区

- 列表页采用“筛选区 + 数据表格 + 右侧抽屉或详情跳转”
- 分析页采用“摘要卡片 + 主视图 + 下钻面板”
- 详情页采用“顶部信息 + Tab 内容区”

### 8.3 全局能力

- 支持保留筛选条件
- 支持从异常摘要直接跳转到明细
- 支持返回上一个分析上下文
- 对空数据场景给出明确说明，如“当前时间范围内无漂移结果”

## 10. 不建议出现在主菜单的能力

根据 `README.md` 中的边界约束，以下能力不建议作为 `config_center` 主菜单的一部分出现：

- 设备连接配置
- 采集协议选择
- 配置实时采集执行
- 配置下发执行
- 协议 fallback 策略
- 厂商连接适配器管理
- 通用设备事实采集入口
- Git 原始提交浏览
- TextFSM / TTP / regex / Jinja2 调试入口

这些能力如果现阶段仍需保留，应采用以下方式处理：

- 作为兼容入口跳转到 `device_api`
- 下沉到管理员工具域
- 隐藏在内部后台，而不是暴露在主导航

## 11. 分阶段落地建议

### P1：先落产品主骨架

优先建设以下页面：

- 配置治理首页
- 快照列表
- 快照详情
- 快照时间线
- 版本对比工作台

目标：

- 先让用户可以围绕快照完成“看、查、比”

### P2：补治理主能力

继续建设：

- 合规结果
- 结构化快照
- 对象级对比
- 漂移列表

目标：

- 让用户可以围绕快照完成“判、析、识别风险”

### P3：补策略闭环与审计

继续建设：

- 规则与基线管理
- 白名单与豁免管理
- 策略管理
- 审计记录

目标：

- 让产品闭环从“分析”延伸到“治理”和“追责”

### P4：收敛内部工具

最后处理：

- 管理工具域
- 调试能力下沉
- 权限隔离和文案隔离

目标：

- 完成产品面与工具面的彻底分层

## 12. 一句话总结

`config_center` 前端不应该被设计成“怎么采、怎么下发”的设备操作台，而应该被设计成围绕“配置快照”的治理工作台，核心体验是“怎么存、怎么看、怎么比、怎么管、怎么审计”。
