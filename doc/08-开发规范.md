# 开发规范

## 1. 代码规范

### 1.1 Python代码规范

#### PEP 8规范
- 使用4个空格缩进，不使用Tab
- 每行代码长度不超过120字符
- 使用有意义的变量和函数名
- 函数和类之间空两行
- 导入语句按标准库、第三方库、本地库分组

#### 命名规范
- **类名**: 使用大驼峰命名（PascalCase），如 `NetworkDevice`
- **函数名**: 使用小写下划线命名（snake_case），如 `get_device_info`
- **变量名**: 使用小写下划线命名，如 `device_ip`
- **常量**: 使用全大写下划线命名，如 `MAX_RETRY_COUNT`
- **私有方法/属性**: 使用单下划线前缀，如 `_internal_method`

#### 类型提示
尽量使用类型提示（Type Hints）：
```python
from typing import List, Dict, Optional

def get_device_info(device_id: int) -> Optional[Dict[str, any]]:
    """获取设备信息"""
    pass
```

#### 文档字符串
使用Google风格的文档字符串：
```python
def collect_device_data(device_ip: str, commands: List[str]) -> Dict[str, any]:
    """采集设备数据
    
    Args:
        device_ip: 设备IP地址
        commands: 要执行的命令列表
        
    Returns:
        包含采集结果的字典
        
    Raises:
        ConnectionError: 当设备连接失败时
    """
    pass
```

### 1.2 Django代码规范

#### 模型规范
- 使用verbose_name定义字段说明
- 使用related_name定义反向关系名称
- 合理使用索引
- 使用Meta类定义表名和排序

```python
class NetworkDevice(models.Model):
    """网络设备模型"""
    name = models.CharField(verbose_name='设备名称', max_length=100)
    vendor = models.ForeignKey(
        Vendor,
        verbose_name='厂商',
        related_name='devices',
        on_delete=models.SET_NULL,
        null=True
    )
    
    class Meta:
        verbose_name = '网络设备'
        verbose_name_plural = '网络设备'
        db_table = 'asset_networkdevice'
        indexes = [models.Index(fields=['name'])]
```

### 1.3 数据库规范

#### 查询优化
- 使用select_related减少查询次数
- 使用prefetch_related优化多对多关系
- 避免N+1查询问题
- 合理使用索引

```python
# 好的做法
devices = NetworkDevice.objects.select_related('vendor', 'idc').all()

# 避免的做法
devices = NetworkDevice.objects.all()
for device in devices:
    print(device.vendor.name)  # 会产生N+1查询
```

#### 事务管理
- 使用@transaction.atomic装饰器
- 批量操作使用bulk_create/bulk_update
- 避免长时间事务

```python
from django.db import transaction

@transaction.atomic
def create_devices(device_list):
    NetworkDevice.objects.bulk_create(device_list)
```

## 2. Git提交规范

### 2.1 提交信息格式
```
<类型>: <描述>

[可选：详细说明]

[可选：相关Issue]
```

### 2.2 提交类型
- **feat**: 新功能
- **fix**: 修复bug
- **docs**: 文档更新
- **style**: 代码格式调整（不影响功能）
- **refactor**: 代码重构
- **perf**: 性能优化
- **test**: 测试相关
- **chore**: 构建过程或辅助工具的变动

### 2.3 提交示例
```
feat: 添加设备采集功能

- 支持H3C设备ARP表采集
- 支持华为设备MAC地址表采集
- 添加采集结果存储到MongoDB

Closes #123
```

### 2.4 分支管理
- **main/master**: 主分支，稳定版本
- **develop**: 开发分支
- **feature/xxx**: 功能分支
- **fix/xxx**: 修复分支
- **hotfix/xxx**: 紧急修复分支

## 4. 测试规范

### 4.1 单元测试
- 为每个功能模块编写单元测试
- 测试覆盖率应达到70%以上
- 使用Django TestCase

```python
from django.test import TestCase
from apps.asset.models import NetworkDevice

class NetworkDeviceTestCase(TestCase):
    def setUp(self):
        self.device = NetworkDevice.objects.create(
            serial_num='TEST123',
            manage_ip='192.168.1.1',
            name='Test Device'
        )
    
    def test_device_creation(self):
        self.assertEqual(self.device.name, 'Test Device')
```

### 4.2 集成测试
- 测试API接口

## 6. 安全规范

### 6.1 密码安全
- 密码必须加密存储
- 使用Django的密码加密机制
- 不在日志中输出密码

### 6.2 SQL注入防护
- 使用Django ORM，避免原生SQL
- 如果必须使用原生SQL，使用参数化查询

### 6.3 XSS防护
- 对用户输入进行验证和转义
- 使用Django模板的自动转义

### 6.4 CSRF防护
- 启用Django的CSRF保护
- API接口使用Token认证

## 7. 性能规范

### 7.1 数据库查询
- 避免N+1查询
- 使用索引优化查询
- 合理使用缓存

### 7.2 异步任务
- 耗时操作使用Celery异步处理
- 合理设置任务超时时间
- 监控任务执行情况

### 7.3 缓存使用
- 热点数据使用Redis缓存
- 合理设置缓存过期时间
- 注意缓存一致性

## 8. 错误处理规范

### 8.1 异常处理
- 使用具体的异常类型
- 记录异常日志
- 返回友好的错误信息

```python
try:
    device = NetworkDevice.objects.get(id=device_id)
except NetworkDevice.DoesNotExist:
    logger.error(f"设备不存在: {device_id}")
    return Response({"error": "设备不存在"}, status=404)
except Exception as e:
    logger.exception(f"获取设备信息失败: {device_id}")
    return Response({"error": "服务器错误"}, status=500)
```

### 8.2 日志记录
- 使用适当的日志级别
- 记录关键操作和错误
- 日志信息清晰明确

```python
import logging

logger = logging.getLogger(__name__)

logger.info(f"开始采集设备: {device_ip}")
logger.warning(f"设备连接超时: {device_ip}")
logger.error(f"采集失败: {device_ip}", exc_info=True)
```

## 9. 代码组织规范

### 9.1 模块划分
- 按功能模块组织代码
- 每个模块职责单一
- 避免循环依赖

### 9.2 工具类
- 通用工具放在utils目录
- 模块特定工具放在模块内
- 工具函数应该是无状态的

### 9.3 配置管理
- 配置统一放在config目录
- 敏感信息使用环境变量
- 不同环境使用不同配置

## 10. 版本管理规范

### 10.1 版本号规则
使用语义化版本号：`主版本号.次版本号.修订号`
- **主版本号**: 不兼容的API修改
- **次版本号**: 向下兼容的功能性新增
- **修订号**: 向下兼容的问题修正

### 10.2 版本发布
- 发布前进行充分测试
- 更新CHANGELOG.md
- 创建Git Tag
- 编写发布说明
