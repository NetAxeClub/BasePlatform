# 项目概述

## 1. 项目定位

BasePlatform（NetAxe）是一个 Django 单体后端，面向网络设备运维场景，核心能力包括：

- 资产与设备主数据管理
- 设备采集与结果标准化
- 工作流与巡检结果写回
- 接口利用率与地址定位分析
- 配置中心、防火墙纳管、拓扑等领域能力

当前理解项目时，优先把它看成 4 个主能力中心：

1. `asset`：资产与 CMDB 主数据
2. `device_api`：设备采集、协议适配、结果标准化
3. `workflow_center`：工作流执行、巡检写回、诊断查询
4. `network_analysis`：接口利用率、地址定位等分析快照

## 2. 当前推荐理解方式

### 2.1 新主链

当前仓库的“新主链”是：

- `device_api`
- `workflow_center`
- `network_analysis`

其中：

- `device_api` 负责原子采集与标准化入库
- `workflow_center` 负责工作流域接口
- `network_analysis` 负责分析型快照

### 2.2 legacy 边界

- `automation` 视为 legacy 链路，只保留历史兼容和生产兜底职责
- 新能力不应继续实现在 `automation`

## 3. 关键目录

### 3.1 仓库根目录

- `backend/`：Django 后端主工程
- `config/`：本地配置与默认配置
- `doc/`：精简后的项目说明文档
- `dockerfiles/`、`docker-compose.yml`、`nginx/`：部署资源

### 3.2 后端关键目录

- `backend/apps/asset/`：设备、账号、位置、组织等主数据
- `backend/apps/device_api/`：采集方案、执行链路、处理器、结果查询
- `backend/apps/workflow_center/`：工作流、巡检写回、诊断接口
- `backend/apps/network_analysis/`：接口利用率、地址定位、分析任务
- `backend/apps/config_center/`：配置备份、模板、快照与合规
- `backend/apps/dcs_control/`：安全设备纳管与安全策略能力
- `backend/apps/topology/`：拓扑对象与拓扑查询
- `backend/utils/`：连接层、Mongo、SNMP、通用工具
- `backend/netaxe/`：Django settings、urls、celery 入口

## 4. 技术栈

- 后端框架：Django 3.2 + DRF
- 异步任务：Celery + Redis
- 数据库：
  - MySQL：结构化业务数据
  - MongoDB：采集结果与部分分析数据
  - Redis：缓存与队列
- 网络协议与连接：
  - Netmiko
  - ncclient / NETCONF
  - SNMP
  - RESTCONF / Telemetry（部分能力仍在推进）

## 5. 典型运行链路

### 5.1 设备采集主链

1. 从 `asset` 获取设备与账号信息
2. 由 `device_api` 按父方案/子方案执行采集
3. 处理器对原始结果做标准化
4. 写入 `plan_<collection_type>` 集合
5. 由 `network_analysis` 消费标准化结果生成分析快照

### 5.2 巡检与查询主链

1. `workflow_center` 写入或查询巡检执行记录
2. `workflow_center` 读取 `network_analysis` 地址定位快照
3. 外部系统通过稳定 API 获取执行、诊断、地址定位等结果

## 6. 本地开发最常用命令

默认在 `backend/` 目录执行：

```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 0.0.0.0:8000
python manage.py test
celery -A netaxe worker -l info -Q default
```
