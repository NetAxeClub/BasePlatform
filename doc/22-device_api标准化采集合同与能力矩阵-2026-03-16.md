# device_api 标准化采集合同与能力矩阵（2026-03-16）

## 1. 目的

本文档用于冻结 `device_api` 输出给 `network_analysis`、`workflow_center` 和 NetClaw-CN 的标准化采集结果合同，并给出当前主厂商矩阵的能力基线。

## 2. 标准化结果合同

### 2.1 标准集合

标准集合统一采用 `plan_<collection_type>` 命名，至少包含：

- `plan_arp`
- `plan_mac`
- `plan_lldp`
- `plan_aggre_port`
- `plan_ip_interface`
- `plan_interface_brief`

其它采集类型继续使用同一命名规则，如：

- `plan_route_table`
- `plan_bgp_neighbors`
- `plan_bgp_summary`
- `plan_ospf_neighbors`
- `plan_ospf_interfaces`
- `plan_isis_neighbors`

兼容说明：

- `device_identity` 的旧处理别名 `version` 仅用于处理器路由
- 标准化入库时统一归一为 `collection_type=device_identity`
- 对应集合固定为 `plan_device_identity`

### 2.2 冻结字段

所有标准化结果必须保留以下公共字段：

- 元数据字段：`hostip`、`hostname`、`idc_name`、`log_time`
- 上下文字段：`summary_plan_id`、`plan_id`、`collection_type`、`collection_method`、`execute_time`

约束：

- 可以补字段
- 不允许删除上述字段
- 不允许重命名上述字段
- `device_api` 运行链路必须保证这 9 个字段始终存在
- `contract.py` 是集合名与上下文字段冻结的单一来源，主链写入逻辑统一引用这里的规则

### 2.3 职责边界

- `device_api`
  - 负责原始采集、解析、标准化、事实回写、结果入库
- `network_analysis`
  - 只消费标准化结果，不重新定义原始字段语义
- `workflow_center`
  - 只消费快照或标准化结果，不直接依赖 legacy 采集模型

## 4. 本轮验收边界

- 验收范围按当前主矩阵，不扩大到仓库里的所有零散模板厂商
- 以 `arp` 为标准化样板，要求各厂商最终都落到 `plan_arp`
- `mac`、`lldp`、`aggre_port`、`ip_interface`、`interface_brief` 采用同一标准化策略
