# 网络设备数据采集方案 - 功能需求文档

## 1. 项目概述

### 1.1 项目背景
网络设备数据采集是网络运维管理的基础能力，需要从不同厂商、不同类型的网络设备中采集各类网络数据（如ARP表、MAC表、LLDP邻居信息、接口信息等），并将采集到的数据转换为统一的数据模型进行存储和管理。

### 1.2 项目目标
- 实现网络设备的API操作能力集合，支持多种采集方式
- 适配不同厂家的不同采集方式（Netmiko、NETCONF、SNMP、RESTCONF、Telemetry）
- 通过插件函数实现统一数据模型字段入库
- 提供灵活的采集方案配置和管理能力
- 支持定时批量采集和单设备采集
- 支持连接复用，确保单设备采集时只建立一次连接

### 1.3 适用范围
- 支持厂商：H3C、华为、思科、锐捷、山石、Mellanox、中兴、盛科、迈普等
- 支持设备类型：交换机、路由器、防火墙等网络设备
- 支持采集类型：ARP、MAC、LLDP、IP接口、二层接口、聚合端口等

## 2. 功能需求

### 2.1 采集方案管理

#### 2.1.1 父采集方案（DeviceCollectionPlans）
**功能描述**：管理采集汇总方案，作为多个子采集方案的容器。

**功能要求**：
- 支持创建、查询、更新、删除父采集方案
- 每个父采集方案包含以下信息：
  - 方案名称（唯一）
  - 厂商（H3C、华为、思科等）
  - 设备类型（交换机、路由器、防火墙等）
  - 描述信息
  - 启用/禁用状态
- 支持一个父采集方案关联多个子采集方案
- 支持按厂商、设备类型等条件查询和过滤

#### 2.1.2 子采集方案（DeviceSubCollectionPlan）
**功能描述**：管理具体的采集任务配置，支持Netmiko、NETCONF、SNMP、RESTCONF、Telemetry五种采集方式。

**功能要求**：
- 支持创建、查询、更新、删除子采集方案
- 每个子采集方案包含以下配置：

**Netmiko配置**：
- 启用/禁用Netmiko采集
- 采集方法名称（要执行的命令）
- 数据路径配置（用于字段映射）
- 字段映射配置（JSON格式，定义原始数据到标准字段的映射关系）
- 数据处理函数（可选，用于自定义数据处理逻辑）
- TextFSM模板路径（可选，用于解析命令输出）

**NETCONF配置**：
- 启用/禁用NETCONF采集
- XML模板配置（支持RPC、GET、GET_CONFIG三种方式）
- 数据路径配置
- 字段映射配置
- 数据处理函数（可选）

**SNMP配置**：
- 启用/禁用SNMP采集
- SNMP版本（v1、v2c、v3）
- OID配置（支持单个OID或OID列表）
- 社区字符串（v1/v2c）或用户认证信息（v3）
- 数据路径配置
- 字段映射配置
- 数据处理函数（可选）

**RESTCONF配置**：
- 启用/禁用RESTCONF采集
- REST API端点URL
- HTTP方法（GET、POST等）
- 请求头配置
- 请求体配置（可选）
- 数据路径配置
- 字段映射配置
- 数据处理函数（可选）

**Telemetry配置**：
- 启用/禁用Telemetry采集
- 订阅路径配置
- 采样间隔配置
- 数据格式（GPB、JSON等）
- 数据路径配置
- 字段映射配置
- 数据处理函数（可选）

**通用配置**：
- 采集类型（arp、mac、lldp、ip_interface、interface_brief、aggre_port等）
- 方案描述

#### 2.1.3 采集模板管理

**NETCONF XML模板管理**：
- 支持为每个子采集方案配置多个XML模板
- 支持三种采集方法：RPC、GET、GET_CONFIG
- 每个采集方案下每种采集方法只能配置一个模板
- 支持XML模板的创建、查询、更新、删除

**SNMP OID配置管理**：
- 支持为每个子采集方案配置OID列表
- 支持单个OID和OID范围配置
- 支持MIB文件导入和OID名称解析
- 支持OID配置的创建、查询、更新、删除

**RESTCONF端点配置管理**：
- 支持为每个子采集方案配置REST API端点
- 支持YANG模型路径配置
- 支持请求参数和请求头配置
- 支持端点配置的创建、查询、更新、删除

**Telemetry订阅配置管理**：
- 支持为每个子采集方案配置订阅路径
- 支持采样间隔和过滤条件配置
- 支持数据格式选择（GPB、JSON等）
- 支持订阅配置的创建、查询、更新、删除

#### 2.1.4 采集方案与设备关联
**功能描述**：管理设备与采集方案的关联关系。

**功能要求**：
- 支持为设备指定采集方案
- 支持查询设备关联的采集方案
- 支持批量关联设备到采集方案
- 采集任务由平台通过Celery异步任务直接执行，无需外部服务节点

### 2.2 数据采集执行

#### 2.2.1 单设备采集
**功能描述**：对单个设备执行采集任务。

**功能要求**：
- 支持通过API接口触发单设备采集（异步方式，通过Celery任务执行）
- 支持同时执行多种采集方式（Netmiko、NETCONF、SNMP、RESTCONF、Telemetry）
- **连接复用要求**：对单台设备进行数据采集时，必须确保只发起一次协议连接请求和连接关闭请求
  - 对于有状态协议（Netmiko、NETCONF、RESTCONF、Telemetry），应在同一个连接会话中完成所有采集任务
  - 对于无状态协议（SNMP），应复用SNMP会话或连接池
  - 通过连接管理器统一管理，确保同一设备的多个采集任务共享连接
- 支持指定采集方案或使用设备关联的采集方案
- 返回采集任务执行结果（成功/失败、任务ID等）
- 所有采集任务由平台本身通过Celery异步任务直接执行，不依赖外部南向驱动服务

#### 2.2.2 批量采集
**功能描述**：对多个设备执行批量采集任务。

**功能要求**：
- 支持定时任务批量采集（Celery异步任务）
- 支持按条件筛选设备（厂商、设备类型、IDC等）
- 支持并发执行多个设备的采集任务
- 支持采集任务状态跟踪和结果统计
- 所有采集任务由平台本身通过Celery异步任务直接执行，不依赖外部南向驱动服务
- 每个设备的采集任务独立执行，但单设备内部遵循连接复用原则

#### 2.2.3 采集方式支持

**Netmiko采集**：
- 支持SSH连接设备执行CLI命令（由平台直接建立连接）
- 支持TextFSM模板解析命令输出
- 支持自定义命令和模板配置
- 支持连接超时和会话超时配置
- 支持连接复用，同一设备的多个命令在同一会话中执行

**NETCONF采集**：
- 支持通过NETCONF协议连接设备（由平台直接建立连接）
- 支持RPC、GET、GET_CONFIG三种操作方式
- 支持XML模板配置和JSON格式返回
- 支持不同厂商的设备参数配置
- 支持连接复用，同一设备的多个操作在同一会话中执行

**SNMP采集**：
- 支持SNMP v1、v2c、v3协议（由平台直接建立连接）
- 支持单个OID查询和OID列表批量查询
- 支持Walk操作遍历MIB树
- 支持GetBulk操作批量获取数据
- 支持SNMP v3的认证和加密（USM安全模型）
- 支持连接复用，通过SNMP会话池管理连接
- 支持超时和重试配置

**RESTCONF采集**：
- 支持RESTCONF协议连接设备（由平台直接建立连接）
- 支持HTTP/HTTPS协议
- 支持GET、POST、PUT、DELETE等HTTP方法
- 支持YANG模型数据查询
- 支持JSON和XML数据格式
- 支持HTTP认证（Basic、Token等）
- 支持连接复用，通过HTTP连接池管理连接
- 支持请求超时和重试配置

**Telemetry采集**：
- 支持gRPC协议连接设备（由平台直接建立连接）
- 支持订阅式数据采集（Push模式）
- 支持GPB（Google Protocol Buffers）和JSON数据格式
- 支持采样间隔配置
- 支持数据过滤和路径配置
- 支持连接复用，通过gRPC连接池管理连接
- 支持流式数据传输和断线重连

### 2.3 数据处理与入库

#### 2.3.1 原始数据处理
**功能描述**：对采集到的原始数据进行处理，转换为统一的数据模型。

**处理流程**：
1. **厂商特定数据处理**：根据厂商和采集类型，调用对应的工具类方法进行初步处理
   - 支持厂商：H3C、华为、思科、锐捷、山石、Mellanox、中兴、盛科、迈普等
   - 处理逻辑位于 `tools/` 目录下的厂商类中
   - 方法命名规范：`get_{collection_type}`（如 `get_arp`、`get_mac` 等）

2. **字段映射**：根据配置的字段映射规则，将处理后的数据映射到标准字段
   - 支持复杂路径映射（如 `data[*].field_key`）
   - 支持系统字段自动填充（如 `hostip`、`log_time` 等）
   - 支持按 `sort` 字段排序映射

3. **厂商后处理**：对于Netmiko采集方式，支持额外的厂商特定后处理
   - 接口格式化（如华为接口格式统一）
   - 数据校验和补全
   - 关联数据查询（如LLDP邻居IP查询）

#### 2.3.2 数据入库
**功能描述**：将处理后的数据存储到MongoDB。

**功能要求**：
- 支持按采集类型存储到不同的MongoDB集合
  - `plan_arp`：ARP表数据
  - `plan_mac`：MAC表数据
  - `plan_lldp`：LLDP邻居数据
  - `plan_ip_interface`：三层接口数据
  - `plan_interface_brief`：二层接口数据
  - `plan_aggre_port`：聚合端口数据
- 支持批量插入数据
- 支持数据去重和更新
- 支持采集元数据记录（设备IP、采集时间、任务ID等）

#### 2.3.3 采集结果记录
**功能描述**：记录采集任务的执行状态和结果。

**功能要求**：
- 主采集方案记录（COLLECTION_PLAN）：
  - 记录设备、采集方案、执行时间等信息
  - 记录采集任务状态（success/failed）
  - 记录子采集方案数量
- 子采集方案记录（COLLECTION_SUB_PLAN）：
  - 记录每个子采集方案的执行状态
  - 记录任务ID和错误信息
  - 关联主采集方案记录

### 2.4 数据查询与统计

#### 2.4.1 采集结果查询
**功能描述**：查询历史采集结果数据。

**功能要求**：
- 支持按采集方案、设备IP、采集类型等条件查询
- 支持分页查询
- 支持时间范围查询
- 支持采集结果详情查看
- 支持原始数据和处理后数据查看

#### 2.4.2 采集统计
**功能描述**：统计采集任务的执行情况。

**功能要求**：
- 覆盖率统计：参与自动化任务的设备数 / 总设备数
- 成功率统计：成功执行采集任务的设备数 / 参与采集任务的设备数
- 纳管设备总数统计
- 采集方案数量统计
- 支持按厂商维度统计

#### 2.4.3 任务状态查询
**功能描述**：查询采集任务的执行状态。

**功能要求**：
- 支持查询主采集方案任务列表
- 支持查询子采集方案任务详情
- 支持按设备、时间、状态等条件过滤
- 支持任务错误信息查看

### 2.5 数据缓存

#### 2.5.1 缓存更新
**功能描述**：将采集到的数据更新到缓存，用于快速查询。

**功能要求**：
- 支持ARP表缓存（以IP为key）
- 支持MAC表缓存（以IDC+MAC为key）
- 支持LLDP表缓存（正向和反向）
- 支持聚合端口缓存
- 支持缓存过期时间配置

#### 2.5.2 CMDB数据同步
**功能描述**：将CMDB中的设备信息同步到MongoDB。

**功能要求**：
- 支持定时同步设备信息
- 支持设备基本信息、位置信息等同步
- 用于LLDP邻居IP查询等场景

## 3. 非功能需求

### 3.1 性能要求
- 支持并发执行多个设备的采集任务
- 单设备采集响应时间 < 30秒（取决于网络和设备性能、采集方式）
  - Netmiko/NETCONF：取决于命令执行时间
  - SNMP：通常 < 5秒（批量OID查询）
  - RESTCONF：取决于API响应时间，通常 < 10秒
  - Telemetry：流式数据，持续采集
- 批量采集支持任务队列管理，避免资源耗尽
- 数据处理和入库支持批量操作，提高效率
- 连接复用机制减少连接建立开销，提高采集效率

### 3.2 可靠性要求
- 支持采集任务失败重试机制（所有采集方式）
- 支持采集任务状态持久化，避免任务丢失
- 支持异常情况的错误记录和告警
- 支持采集任务超时控制
  - Netmiko/NETCONF：连接超时和命令执行超时
  - SNMP：请求超时和重试机制
  - RESTCONF：HTTP请求超时
  - Telemetry：连接超时和断线重连
- 支持连接异常自动恢复和重连
- 确保连接正确关闭，避免连接泄漏

### 3.3 可扩展性要求
- 支持新增厂商适配（通过添加工具类实现，支持所有采集方式）
- 支持新增采集类型（通过配置字段映射实现）
- 支持新增采集方式（通过扩展平台采集能力实现，当前支持5种方式）
- 支持插件化的数据处理函数（支持所有采集方式）
- 支持采集方式的组合使用（同一设备可同时使用多种采集方式）
- 支持采集方式的优先级配置（当多种方式可用时，选择最优方式）

### 3.4 安全性要求
- 设备账号密码加密存储（所有采集方式）
- 采集任务执行权限控制
- 支持操作日志记录
- 支持敏感数据脱敏
- SNMP v3支持认证和加密（USM安全模型）
- RESTCONF支持HTTPS和Token认证
- Telemetry支持TLS加密传输
- 连接信息不记录到日志

### 3.5 可维护性要求
- 代码结构清晰，模块化设计
- 支持采集方案配置的导入导出
- 支持采集任务执行日志查看
- 支持采集方案配置验证

## 5. 数据模型

### 5.1 标准数据模型字段

**ARP表（plan_arp）**：
- hostip：设备IP
- hostname：设备名称
- idc_name：机房名称
- ipaddress：IP地址
- macaddress：MAC地址
- aging：老化时间
- type：类型
- vlan：VLAN ID
- interface：接口名称
- vpninstance：VPN实例
- log_time：采集时间

**MAC表（plan_mac）**：
- hostip、hostname、idc_name
- macaddress：MAC地址
- vlan：VLAN ID
- interface：接口名称
- type：类型
- log_time：采集时间

**LLDP表（plan_lldp）**：
- hostip：设备IP
- local_interface：本地接口
- chassis_id：Chassis ID
- neighbor_port：邻居端口
- portdescription：端口描述
- neighborsysname：邻居系统名
- management_ip：管理IP
- management_type：管理类型
- neighbor_ip：邻居IP
- log_time：采集时间

**三层接口（plan_ip_interface）**：
- hostip、interface
- line_status：线路状态
- protocol_status：协议状态
- ipaddress：IP地址
- ipmask：子网掩码
- ip_type：IP类型
- mtu：MTU值
- log_time：采集时间

**二层接口（plan_interface_brief）**：
- hostip、interface
- status：接口状态
- speed：速率
- duplex：双工模式
- description：描述
- log_time：采集时间

**聚合端口（plan_aggre_port）**：
- hostip：设备IP
- aggregroup：聚合组名称
- memberports：成员端口
- status：状态
- mode：模式
- log_time：采集时间

### 5.2 采集方案数据模型
- DeviceCollectionPlans：父采集方案
- DeviceSubCollectionPlan：子采集方案（包含Netmiko、NETCONF、SNMP、RESTCONF、Telemetry配置）
- NetconfXMLTemplate：NETCONF XML模板
- SnmpOidConfig：SNMP OID配置（可选，可集成到子采集方案）
- RestconfEndpointConfig：RESTCONF端点配置（可选，可集成到子采集方案）
- TelemetrySubscriptionConfig：Telemetry订阅配置（可选，可集成到子采集方案）
- PlansToDevice：采集方案与设备关联

## 6. 约束条件

### 6.1 技术约束
- 必须使用Netmiko、NETCONF、SNMP、RESTCONF或Telemetry协议进行设备连接
- 所有采集任务必须由平台本身通过Celery异步任务直接执行
- 数据存储必须使用MongoDB
- 异步任务必须使用Celery
- 单设备采集必须确保只建立一次协议连接，支持连接复用
- SNMP采集需要设备支持SNMP协议并配置SNMP社区字符串或用户认证
- RESTCONF采集需要设备支持RESTCONF API并配置HTTP认证
- Telemetry采集需要设备支持gRPC和Telemetry订阅功能

### 6.2 业务约束
- 设备必须配置相应协议的账号/认证信息才能执行采集：
  - Netmiko：需要SSH账号
  - NETCONF：需要NETCONF账号
  - SNMP：需要SNMP社区字符串（v1/v2c）或用户认证信息（v3）
  - RESTCONF：需要HTTP认证信息（Basic、Token等）
  - Telemetry：需要gRPC连接配置
- 采集方案必须关联到设备才能执行
- 采集任务由平台Celery Worker直接执行，无需外部服务节点
- 至少需要启用一种采集方式才能执行采集任务

### 6.3 数据约束
- 采集数据必须符合标准数据模型字段定义
- 字段映射配置必须符合JSON格式规范
- 采集类型必须从预定义的类型中选择
- 不同采集方式的数据格式要求：
  - Netmiko：TextFSM解析后的结构化数据或原始文本
  - NETCONF：XML解析后的JSON数据
  - SNMP：OID值对字典
  - RESTCONF：JSON格式数据
  - Telemetry：GPB或JSON格式数据
