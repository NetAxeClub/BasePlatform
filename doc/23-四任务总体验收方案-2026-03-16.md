# 四任务总体验收方案（2026-03-16）

## 1. 目的

本文档用于统一管理以下四个并发任务的过程验收、集成验收与最终签字门禁：

1. `device_api` 采集主链替代 `automation`
2. 网络设备接口利用率全流程与统一触发
3. IP 地址定位全流程与准确性
4. NetClaw-CN 对接边界与双边改造约束

本文档不是需求文档，而是总负责人使用的验收与放行依据。

## 2. 当前前置事实

截至 2026-03-16，本轮验收必须接受以下仓库事实：

- 任务 1 主工作区分支 `codex/device-api-replace-automation-2026-03-15` 已前进到新的基线提交。
- 任务 2/3/4 对应 worktree 仍可能停留在更早的基线提交上，因此最终验收前必须先吸收任务 1 的标准化合同基线。
- 新 worktree 的 Django 测试当前存在统一启动阻塞：
  - `asset -> automation -> driver -> plugins.extensibles -> apps.monitor`
  - 该阻塞若未消除，任何任务都只能标记为“开发完成待验收”，不能标记为 `DONE`。

## 3. 总体验收顺序

统一按以下顺序推进，不允许跳过：

1. `Gate 0`：测试底座解阻
2. `Gate 1`：任务 1 合同基线冻结并被 2/3/4 吸收
3. `Gate 2`：各任务单独功能验收
4. `Gate 3`：四任务集成验收
5. `Gate 4`：总体验收签字

## 4. Gate 0：测试底座门禁

### 4.1 目标

让 4 个 worktree 都能在各自 `backend/` 目录下运行目标 Django 测试，而不是只靠 `py_compile`。

### 4.2 退出条件

- 本地 `config/config.json` 在 4 个 worktree 下可用。
- 本地插件路径在 4 个 worktree 下可用。
- `manage.py test <targeted_tests>` 不再因 `apps.monitor`、插件自动加载或相对路径问题在 `check` 阶段失败。

### 4.3 验收记录要求

- 统一记录每个 worktree 的测试启动命令。
- 明确记录仍残留的环境依赖和绕过方式。
- 未通过本门禁前，任何任务不得标记为 `DONE`。

## 5. Gate 1：任务 1 基线门禁

### 5.1 目标

冻结 `device_api` 标准化结果合同，作为任务 2/3/4 的唯一上游基线。

### 5.2 冻结项

- `plan_<collection_type>` 集合命名规则
- 公共字段：
  - `hostip`
  - `hostname`
  - `idc_name`
  - `log_time`
  - `summary_plan_id`
  - `plan_id`
  - `collection_type`
  - `collection_method`
  - `execute_time`

### 5.3 退出条件

- 任务 1 分支通过合同测试与合同文档复核。
- 任务 2/3/4 完成 rebase 或 cherry-pick，确认已吸收任务 1 基线。

### 5.4 验收红线

- 不允许任何任务删除或重命名冻结字段。
- 不允许 2/3 分支继续在旧基线上累计验收结论。

## 6. Gate 2：单任务功能验收

### 6.1 目标

每个任务先在自身边界内通过功能验收，不混入总体验收结论。

### 6.2 统一输出要求

每个任务必须提交以下证据：

- 执行命令
- 结果摘要
- 关键接口返回样例
- 剩余风险
- 未覆盖项

### 6.3 边界复核

总负责人需要逐项确认：

- 是否越界修改
- 是否覆盖正常路径、异常路径、边界条件
- 是否遗漏关键回归
- 是否触碰未审批项

## 7. Gate 3：四任务集成验收

### 7.1 目标

验证 1/2/3/4 四块拼起来后，链路真实可用，而不是局部都对、整体不通。

### 7.2 退出条件

- 任务 2/3 已吸收任务 1 基线。
- 任务 4 契约与实际接口一致。
- 端到端链路可复现：
  - 采集
  - 标准化
  - 分析
  - 查询
  - NetClaw 契约对照

### 7.3 集成验收最小链路

1. 触发 `device_api` 批量采集
2. 确认 `PlanCollectionCelery` / `SubPlanCollectionCelery` 记录齐全
3. 确认 `plan_arp`、`plan_mac`、`plan_lldp`、`plan_aggre_port`、`plan_ip_interface`、`plan_interface_brief` 有同批次标准化数据
4. 确认自动生成 `AnalysisRun`
5. 确认接口利用率与地址定位查询结果可用
6. 确认 NetClaw 规划不再依赖 legacy 采集模型或原始 Mongo 表

## 8. Gate 4：总体验收签字

### 8.1 目标

形成对外可发布的统一验收结论。

### 8.2 退出条件

- 所有红色阻塞清零
- 总功能验收清单逐项勾选
- 所有需审批项单独列出
- 未获批准项不混入“已完成”

### 8.3 签字结论格式

- 结论：`PASS / CONDITIONAL_PASS / FAIL`
- 风险：`low / medium / high`
- 未决事项：`<列表>`
- 放行建议：`<允许联调 / 允许灰度 / 不允许放行>`

当前优先级最高的事项不是新增功能，而是先清理 `Gate 0` 测试底座阻塞，并确认 2/3/4 已吸收任务 1 基线。
